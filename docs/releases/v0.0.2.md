# Ashide v0.0.2

在 v0.0.1 基础上的维护与稳定性版本，聚焦远程（Environment Runtime / SSH）Session Navigator 的行为正确性与 CLI Agent 会话发现的资源边界。

## 修复

- **远程正在运行的 CLI Agent 会话恢复 live 语义。** 远程 Environment 内正在运行 agent 的终端此前会被误判为 virtual「历史」行：agent 在子 shell 中运行时，判断 liveness 用了易失的 active-block session 分类，导致该行同时丢失激活高亮、丢失 agent 运行状态指示点，并把重命名错误路由到远程 alias RPC（表现为重命名不生效）。现在 liveness 只由终端稳定的 Environment Runtime transport 身份决定，与 active block 当前属于哪个 session 无关；本地与远程共用同一套 live-row 语义。

## 改进

- **CLI Agent 会话发现的物理来源上限。** Claude/Codex/Jcode/Omp 等 provider 的会话发现统一走同一发现计划，对每个 provider 施加物理来源上限；超限时返回 typed failure 并保留既有 canonical 行，避免超大 provider store 长期占用 worker I/O 或把目录顺序子集误当作最新会话。metadata 前缀改为流式读取，SessionBridge 的显式全文读取不受该发现门限影响。
- 远程 helper 会话执行上下文注册路径整理，收敛传输边界字段。

## 平台范围

- macOS 与 Linux：本次构建、打包和发布。
- Windows：CI 构建、打包、checksum 与 installer 发布为必经 gate；暂不以 Windows 真机安装或 WSL 手工运行验证阻断发布。

## 已知边界

- 第三方 Agent 的 realtime attach/input/cancel、Fork/Edit/Write-back 和对原生会话文件的写入不属于本版本能力。
- 未接入结构化状态协议的 provider（如 omp）不显示 agent 运行状态指示点；已接入的 provider（Claude/Codex/OpenCode/Jcode 等）正常显示。
