# Ashide v0.0.5

v0.0.5 聚焦 Session Navigator 的发现正确性、刷新反馈和 Omp 原生会话边界；这是面向 macOS dogfooding 的修复发布。

## 修复

- **本地普通终端不再淹没会话列表。** Session Navigator 仅保留带有持久 agent binding 或 Ashide conversation 的本地 terminal；关闭 agent pane/tab 后，由 native 历史会话接管，而不是把普通 shell 或 tab 坐标写成“历史会话”。
- **刷新不再卡住或产生误导 toast。** 用户手动刷新只在 Navigator 刷新图标显示进度；成功、partial、source-missing、stale 和取消均静默保留已提交列表。只有显式失败才显示一条可自动消失的“已保留上次结果”错误提示。
- **被动刷新不再抢占用户操作。** provider 设置、pin、terminal bootstrap 和 source reconciliation 使用同一 authority-scoped passive scan；同一 authority 的重复后台请求会合并，避免持续替换 token 导致所有结果都被判 stale。
- **Omp 保留且收紧原生边界。** Omp 继续支持 discovery、`omp --resume <id>` 和远端删除/归档；扫描使用有界并行与 provider logical limit，远端 mutation 只允许 `sessions/<project-bucket>/*.jsonl` 正本，拒绝 tool log 等非会话文件。
- **移除 Jcode 原生 provider。** Jcode 的 subagent/session store 噪音和格式边界不适合作为稳定 Navigator authority；本版从 discovery、Resume、图标、New Session、remote helper 与静态契约中硬删除该适配。
- **远端发现协议 fail-closed。** CLI agent session wire contract 升至 revision 7；旧 helper 会要求重新安装，不再把不完整/不匹配的远端发现结果混入本地或部分提交。

## 验证

- `MACOSX_DEPLOYMENT_TARGET=10.14 CARGO_INCREMENTAL=0 cargo check -p warp --features gui,local_fs` 已通过。
- LR-204 的 4 个 focused tests 已通过：匹配窗口合并、显式 refresh 抢占但不遗失 passive recipient、scope / observed-provider 输入隔离、blocking worker + token fanout 静态约束。
- `./script/check_release_privacy` 已通过。`./script/check_local_remote_parity` 的所有已实现静态契约（含 LR-204）通过；其 aggregate completion gate 仍因 LR-201～LR-204 的 GUI / runtime 交互记录未全部闭合而返回非零，未将此误报成代码检查失败。
- 当前 checkout 的 `AshideDev.app` 已重新 bundle、通过 strict codesign 验证并真实启动。隔离启动日志显示 9 个 provider 一轮 discovery 共 342 ms，并提交 89 条会话；本轮未伪造多窗口 cold-restore 验收，等价输入的多窗口“一轮 scan”仍保留为 dogfooding runtime gate。
